# OBHOD 0.2 — отчёт о крупном обновлении

Дата: 2026-11-13. Ветка: `wip/major-update`. Релиз и тег **не публиковались**,
`main` не пушился; это проверяемая сборка для ревью.

## 1. Что сделал главный агент

- **Ядро `src/core`**:
  - `state`: `Component`, `Phase` (Installed…Unknown), `CoreState`; общий статус
    выводится из проверок, а не из наличия файлов.
  - `health`: этапы DNS → TCP → TLS → Protocol → Proxy → Target, честные
    `Unknown`/`None`; открытый порт без протокола не считается рабочим прокси.
  - `profiles`: minimal/telegram/gaming/browser/full/custom, `plan()` перед
    применением, импорт/экспорт с валидацией, атомарное хранение.
  - `history`: JSONL-журнал действий, tolerant-чтение, компакция.
  - `background`: планировщик и heartbeat-поток (только пока окно открыто).
- **UI**: главная с бейджем и чипами компонентов; «Ещё» → Состояние сети,
  Серверы, Компоненты, История, Диагностика, Настройки; экраны профилей,
  плана изменений, редактора, истории, менеджера серверов.
- **Интеграция**: `apply_checks_to_core` строит `Signals` из проверок и
  `check::proxy_signals`; `refresh_health` учитывает службу и процесс
  `winws.exe`; `Result` показывает реальные ошибки; `R` собирает отчёт.
- **CI**: fmt, clippy `-D warnings`, тесты, release-сборка, selftest,
  demo-static, SHA256SUMS, артефакт; публикация только на тег.
- **Документация**: README (серверы, профили, ограничения), AGENTS, NOTES,
  этот отчёт.

## 2. Сабагент 1 — Windows System Engineer

- `src/sys`: `dns_state` (снимок по интерфейсам: GUID, DHCP/static, IPv4/6,
  DoH; восстановление ровно как было), `hosts_file` (BOM/CRLF, маркеры,
  отказ при ошибке чтения, проверка пользовательских строк), `journal`
  (append-only JSONL, восстановление незавершённых операций), `transaction`
  (Snapshot→Prepare→Apply→Verify→Commit, обратный откат, повтор при сбое
  rollback), `proc` (владение процессами/службами/Run-значениями, pid+path).
- Переписаны `modules/dns.rs`, `hosts.rs`, `off.rs`, `zapret.rs`: только свои
  ресурсы, `taskkill /IM` убран, выключение с отчётом по шагам.
- `config`: версия, миграция, атомарная запись, `.bak`, сохранение
  повреждённого файла, `take_load_error()`.
- `util`: безопасные аргументы, `run_checked`, PowerShell через env/base64,
  парсинг `reg query`, кавычки Windows.
- 96 тестов: транзакции с прерыванием на каждой фазе, DNS round-trip,
  hosts rollback/BOM, ownership, миграции, квотирование.

## 3. Сабагент 2 — Network & Update Engineer

- `src/net`: `links` (vless/trojan/vmess/ss/hysteria2/tuic/tg, дедуп без
  секретов), `proxy` (DNS → TCP с латентностью → TLS ClientHello с SNI;
  честные вердикты), `manager` (узлы, источники, фильтры, ранжирование,
  история, failover с cooldown/гистерезисом), `trust` (SHA-256, Ed25519-манифест,
  запрет downgrade; без ключа — `Unverified`).
- `subs`/`telegram`: Last Known Good, атомарные записи, несколько источников,
  статистика; пустой прогон не затирает рабочий список.
- `servesub`: токен в пути, constant-time сравнение, лимиты заголовков и
  соединений, loopback-only.
- `update`: staging, CRC/zip-лимиты, проверка MZ, sha256, бэкап, подмена с
  откатом; `selfupdate` — digest/sha256/манифест.
- `report`: маскирование ссылок, секретов, UUID, IP и личных путей.
- `detect`: без личных абсолютных путей, шире реестр/App Paths, аккуратный
  матчинг `Happ`.
- 108 тестов: LKG, атомарность, failover, zip/откат, подписи, HTTP-сервер,
  скраббинг.

## 4. Архитектура

```
UI (ratatui) → App / CoreState → worker
                              ├─ modules (setup/off/update/check)
                              ├─ sys (транзакции, DNS, hosts, ownership)
                              └─ net (links, probes, manager, trust)
```

- Один источник статуса — `CoreState`, обновляется только результатами
  проверок/действий.
- Системные изменения — только через `sys::transaction`/`journal`.
- Профиль не меняет систему сам: сначала `plan()`, затем Enter.
- Demo не пишет файлы и не трогает систему (кроме чтения).

## 5. Исправленные ошибки

- Ложный успех: `run_all` возвращает `false` при упавшем шаге, Result честный.
- `taskkill /IM` больше не убивает чужие Happ/TgWsProxy/winws: только
  записанные за obhod pid+path.
- DNS больше не «сбрасывается в автоматический»: восстанавливается снимок.
- hosts: ошибка чтения останавливает запись; бэкап проверяется.
- Подписки не затираются пустым ответом.
- Самообновление: размер, MZ, sha256, запрет downgrade, откат.
- Убраны личные пути из `detect`.
- Конфиг: миграция, `.bak`, понятное сообщение о повреждении.
- Проверка сети не выдаёт открытый порт за рабочий прокси.
- Кнопки включения/выключения рядом; настройки убраны из «Ещё»-дубля.
- Меню/выделение приведены к одному стилю, описания выровнены.
- `last_update_check` после настройки, чтобы подвал не ныл сразу.

## 8. Известные ограничения

- Трея нет; `--minimized` принимается, но окно открывается. Фон работает
  только при открытом окне.
- Нет отдельного привилегированного helper: TUI запускается целиком через UAC.
- TLS-проба не завершает handshake и не проверяет цепочку сертификатов.
- Аутентификация VLESS/Trojan/VMess, MTProto handshake, SS/Hysteria2/TUIC
  клиенты не реализованы; порт никогда не называется рабочим прокси.
- Failover меняет выбранный узел, но не трафик сторонних приложений.
- Публичный ключ релиза не запинен: подпись `Unverified`, только sha256.
- `proxy-nodes.json` хранит конфиги с секретами локально без шифрования.
- Восстановление «static DNS с пустым списком» падает в DHCP (состояние
  невыразимо в Windows API).
- `sc create` с новым квотированием требует ручной проверки установки службы.

## 9. Что требует ручного тестирования на Windows

1. Установка службы zapret с новым `binPath` и запуск winws.
2. Восстановление DNS после смены сети/перезагрузки, IPv6 и DoH.
3. Выключение при чужом zapret/TgWsProxy — не должно их трогать.
4. Обновление Happ/TgWsProxy при запущенном стороннем экземпляре.
5. Полный цикл failover на реальных узлах.
6. Self-update с подписанным манифестом после добавления ключа.

## 10. GitHub Secrets для подписанных релизов

- `ED25519_PRIVATE_KEY` — base64 приватного ключа (32-byte seed/OpenSSL PEM),
  только в Secrets, никогда в репозитории.
- Публичный ключ (32 raw bytes, base64) вписать в
  `src/net/trust.rs::RELEASE_PUBKEY_B64`.
- В релиз добавлять `obhod.exe`, `obhod-manifest.json`, `obhod-manifest.json.sig`.
- Пока ключ не задан, обновления проверяются только по SHA-256 и честно
  помечаются `Unverified`.

## 11. Что ещё не готово

- Tray/фоновый режим без открытого окна.
- Разделение привилегий (helper/service).
- Полноценная протокольная верификация прокси.
- UI-настройка нескольких источников подписок (сейчас файл `subs_sources.txt`).
- Автоматическая публикация подписанного манифеста в CI (описание есть в
  `trust.rs`, workflow пока публикует только exe и SHA256SUMS).
